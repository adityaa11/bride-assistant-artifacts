## Deferred and blocked decisions

### D-01 Vercel application and DocumentStore platform

**Status:** `superseded` by D-06 · **Historical decision:** Vercel hosts the Next.js application and Vercel Private Blob backs the production `DocumentStore`.  
**Reason for replacement:** User selected Neon Object Storage as the production S3-compatible byte authority alongside Neon PostgreSQL (19 Nov 2026). Vercel remains the application host. **Affects:** historical M2-R01/M2-W01, M4-W01, M5-W03/04. **Revisit trigger:** Restore only if D-06 is superseded by an explicit provider decision.

### D-05 Production PostgreSQL provider and location

**Status:** `confirmed` · **Decision:** Neon PostgreSQL 18.7 in Singapore (`ap-southeast-1`) is the production system of record; Vercel runs the application in Singapore (`sin1`).  
**Rationale:** Neon preserves the confirmed PostgreSQL 18.7 baseline and gives Vercel-native serverless/preview branch support. Supabase was not selected because its managed major/version path conflicts with PostgreSQL 18.7 and its Auth/Storage services would duplicate Better Auth. **Implementation constraint:** use Neon as the PostgreSQL authority; retain Better Auth as the identity authority. Record the provisioned endpoint, connection configuration, and final backup/PITR terms before real data. **Affects:** M2-R01/M2-W01 and M5-W03. **Revisit trigger:** Neon plan lacks required recovery terms, regional availability changes, or the PostgreSQL major changes.

### D-06 Production DocumentStore provider and location

**Status:** `confirmed` · **Decision:** Neon Object Storage in the same selected Singapore Neon project backs production `DocumentStore` for every uploaded media/proof byte; Vercel hosts the Next.js application only. Docker provides local PostgreSQL and a disposable local `DocumentStore` adapter for development; T18's ignored local fixture adapter follows the same byte boundary.
**Evidence:** User direction on 22 Nov 2026 establishes one upload-byte boundary; Neon Object Storage is S3-compatible, supports private buckets, and supports short-lived presigned URLs for private reads and direct uploads. **Boundary:** Neon credentials are server-only; the application authorizes the booking owner/admin before minting a URL. The development/fixture adapter is not production storage and must not receive real customer or payment-proof media. Portfolio, testimonial and event record association/replace/remove lives above `DocumentStore`; it cannot become a separate byte store. **Affects:** M1-W07/T18, M2-W04, M4-W01/W05/W06, M5-W03/04. **Enables:** one Neon authority for production relational facts and uploaded bytes without storing bytes in PostgreSQL. **Revisit trigger:** lack of Singapore availability for the provisioned account, unacceptable recovery/data-transfer terms, or a change to sensitive-byte handling.

### D-02 Runtime and auth/data integration

**Status:** `confirmed` · **Question:** Which current Next.js, Better Auth, PostgreSQL driver/ORM, and Better Auth adapter versions are compatible after D-01?  
**Approved starting baseline (user confirmed, 19 Nov 2026):** Node `24.22.3`; Next.js `16.4.6`; React/React DOM `19.3.1`; TypeScript `5.9.3`; Better Auth `1.7.26`; Zod `4.6.7`; `pg` `8.23.1`; `@types/node` `24.6.6`; PostgreSQL `18.7`. PostgreSQL 18 is currently supported through November 2030; the selected managed provider must offer it. Next 16 requires Node 20.9+ and accepts React 19; Better Auth 1.7.26 declares compatibility with Next 16, React 19, and `pg` 8. Node 24 is both Active LTS and Vercel-supported. Node 26 is deliberately excluded from this baseline. TypeScript 5.9 is retained rather than the TypeScript 6/7 transition line until a later, explicit review.  
**Affects:** M2-R02 and all backend packages. **Enables:** dependency lock and persistent auth. **Verification prerequisite:** create the exact lockfile, install cleanly, and pass build/type/test checks before deployment. **Revisit trigger:** provider incompatibility, peer-dependency conflict, or a security advisory; update patches within these approved majors and rerun the same evidence.

**Security/defect recheck (19 Nov 2026):** Node 24.22.3 is the current patched security release. Next 16 is Active LTS and 16.4.6 is beyond the listed critical-advisory patched floors, but an open 16.4.6 Route Handler defect drops explicitly supplied `Content-Length`; it can break download progress and PDF range retrieval. **Confirmed delivery choice:** after server-side ownership/admin authorization, issue a short-lived direct Neon Object Storage URL rather than proxying private document bytes through a Next Route Handler. M4 must regression-test authorized PDF download and range behavior; if range semantics fail, defer range support rather than adding a route-handler proxy. React 19.3.1 is current; the prior React Server Components critical issue predates this baseline. Better Auth 1.7.26 is above the known fixed floors cited in its late-2026 security advisories; do not enable Magic Link/OAuth/Expo/SSO features without a fresh advisory check and configuration-specific test. Zod 4.6.7 has no listed open direct advisory, but follows a repository credential incident whose malicious commits were not published to npm; use lockfile integrity/provenance controls. No direct advisory was found for `pg` 8.23.1 or TypeScript 5.9.3; keep database TLS certificate verification enabled and use parameterized queries. PostgreSQL 18.7 includes the November security fixes; for an existing 18.x database, follow its release notes on extension rebuilds, affected indexes, and incremental-backup replacement. `documented`, medium-high confidence.

### D-03 Sensitive document policy

**Status:** `deferred` production hardening; core design is `confirmed` · **Question:** What consent, retention/deletion, file limits/types, scanning, recovery, backup, and incident controls apply to proof/media?  
**Single retention rollout (user-intent, 20 Nov 2026):** accept JPEG, PNG, or PDF files; maximum 10 MiB each and three files per payment request. First run a five-minute retention verification for proof bytes and proof-specific audit metadata. If expiry/deletion and history tests pass, set the active retention to eight months from the final proof-review event (or from upload if never reviewed). At expiry, delete the bytes and proof-specific metadata/audit events. The booking's own status history is not deleted by proof retention. Append-only audit records join proof events to the booking history and never store file contents, names, signed URLs, or credentials.  
**Confirmed technical policy:** booking owner uploads only while `Menunggu Pembayaran`; admins do not upload; JPEG/PNG/PDF only; three files at 10 MiB each; extension, detected type/signature, size, generated opaque key, authentication, and authorization are required; proof review never changes booking status by itself; proof access is private and authorized; audit events are append-only; incident handling immediately contains access, preserves audit evidence, and evaluates the statutory 3 × 24-hour notification requirement; policy review recurs every 12 months and after an incident/provider change. Explicit, per-item recorded permission is mandatory before testimonial/portfolio media becomes public.  
**Deferred production choices:** (1) PDP processing basis, final notice wording, and data-subject request contact; (2) scanner provider and its contract/cost; (3) legal/business-hold criteria; (4) Neon account-backed RPO/RTO, backup, and restore ownership; (5) accountant/legal determination whether proof bytes or proof audit records must be retained ten years in Indonesia. These are production-hardening seams, not a removal of the payment-proof capability. **Affects:** M2-R03, M4-W01/02/07, M5-W03. **Enables:** building and testing the full product flow now, then binding final production controls at the named seams. **Revisit trigger:** before production release.
