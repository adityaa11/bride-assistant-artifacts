# H-M2-05 — server actor, owner and input decision

- Ticket: M2-T05. Code repository: `https://github.com/adityaa11/bride-assistant.git`; exact commit `4cac47c1cc4a3b3d0998372d23f4ba4561cc2dc0`.
- Server entrypoint: `shared/server/authorization.ts:authorizeRequest({ requiredRole, recordOwnerId?, payload, schema })`. It obtains the T04 persisted `SessionActor` through `sessionActor()` and calls `decideActorInput`. `shared/server/authorization-decision.ts` contains the pure decision used by the server wrapper and disposable contract tests.
- Inputs: `requiredRole` is `customer | admin`; optional `recordOwnerId` must come from the caller's authoritative record lookup. `undefined` means no record scope, `null` means no record found, and a string is the stored owner ID. `payload` is unknown; `schema` is the named Zod schema supplied by the command/read caller. A browser-supplied owner or role is never authority.
- Success: `{ ok: true, actor, parsedData, record }`, where `record` is `unscoped | found | missing`. A missing record is explicit so the caller can return an empty result without a default or mutation. Failure: `{ ok: false, code: "AUTHENTICATION_REQUIRED" | "FORBIDDEN" }` or `{ ok: false, code: "INVALID_INPUT", fields: string[] }`. Failure exposes no record contents or schema message values. Role/owner denial precedes parsing.
- Current production use: all four protected admin/customer layouts call `authorizeRequest` with the required role and `z.undefined()`; their existing audience redirects map typed denial to route response. T06 and M3/M4 consume this contract before repository or `DocumentStore` access and own their trusted record lookup, domain rules, empty-result mapping and error response. No domain repository or byte access is introduced by T05.
- The test-scoped owner fixture is a temporary PostgreSQL table rolled back after validation. It is not a durable domain model, migration, seed or production caller.
